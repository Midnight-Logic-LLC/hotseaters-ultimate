Database Schema Reference

Complete entity structure and relationships backing the HotSeaters application on Supabase Postgres.

This reference replaces the legacy Base44 schema with the new Supabase model. The legacy company_id column is renamed tenant_id across every entity; multi-tenancy is enforced by Row Level Security (RLS) policies, not by application-layer filtering alone.

Built-in Fields

Every entity automatically includes:

  • id — uuid, primary key (Postgres gen_random_uuid())
  • created_at — timestamptz (replaces Base44 created_date)
  • updated_at — timestamptz (replaces Base44 updated_date)
  • created_by — uuid referencing auth.users(id) (replaces Base44 email-based attribution)

All tenant-scoped entities additionally carry tenant_id uuid not null with RLS policies enforcing isolation.

auth.users (Supabase built-in)

Supabase-managed authentication table. Not modified directly; users are created through:

  1. The email/password signup flow (legacy, still supported)
  2. The Google OAuth sub-user self-signup flow (new — lands in pending_approval, approved by the firm owner, 14-day pg_cron expiry)
id, email, encrypted_password, email_confirmed_at, raw_user_meta_data,
last_sign_in_at

Never insert directly; use Supabase Auth admin APIs (for OAuth sub-user approval) or the public signup flow.

Key Schema Patterns

Snapshot pattern

Denormalize critical display values onto transactional rows:

  • service_name on trial_services
  • trial_name, client_name, service_name on time_entries
  • consultant_first_name, consultant_last_name on hsh_contracts
  • consultant_name, responding_tenant_name, trial_name, etc. on notifications

Reason: historical accuracy when source rows change (a service is renamed, a client firm rebrands, a consultant leaves).

Soft delete pattern

Prefer is_active or status flags over hard deletes. Documents used in production are soft-deleted; unused draft templates may be hard-deleted. contacts.contact_status = 'transferred' hides transferred people without losing history. hsh_contracts.status = 'cancelled' retains the audit trail.

Tenant isolation

Every tenant-scoped entity includes tenant_id. RLS policies are the primary guardrail; application-layer filters are defense in depth. See the Backend Functions and Technical Reference documents for the specific RLS patterns in use.

Cross-tenant references (HotSeatHub)

hsh_contracts links hiring_tenant_id and subcontractor_tenant_id. Time entries and expenses are mirrored in both tenants via linked_time_entry_id / linked_expense_id.

Projected Daily Revenue (PDR)

trial_services stores precomputed projected_daily_revenue fields for performant forecasting; split billing carries separate pre-trial and in-trial rates.

Invoice recipient preferences

trials.invoice_recipient_preferences (jsonb) remembers recipient selections for invoice emails — selected contacts and additional addresses with To/CC/BCC designations.

HSH negotiation history

hsh_applications.negotiation_history (jsonb) is an append-only array tracking every counter-offer: rate, message, proposer, timestamp, and type (initial | counter | accept | decline). last_proposed_by determines signing order on acceptance.

HSH agreement PDF lifecycle

hsh_contracts.agreement_pdf_url points at the auto-generated HSH agreement PDF. On cancellation, a cancellation-addendum page is appended to the existing PDF (not overwritten) so both sides retain a single document containing the full lifecycle.

QuickBooks graceful degradation

The QuickBooks-integration columns referenced in later documents (quickbooks_customer_id, quickbooks_invoice_id, quickbooks_sync_state) exist on the relevant entities but all code paths short-circuit behind a "configured path deferred" banner until the dedicated QuickBooks phase lands. See QuickBooks Integration.
