Expense tracking in HotSeaters covers two input modes — Receipt (photo + OCR) and Mileage (start/end address + route) — and two ownership models — regular (own tenant only) and HSH (subcontractor tenant + hiring tenant, mirrored). This page documents every scenario, the Supabase tables involved, and the Edge Functions that back each step.

For entity definitions see Database Schema. For the approval queue UI see Approvals. For invoice rollup see Billing. For the sibling time-entry flow see Time Tracking and Time Clock Workflows.

Overview

The expense_entries table stores three entry_type variants:

  • regular — owned entirely by one tenant; no cross-tenant mirror.
  • subcontractor — written into the subcontractor's tenant when they log an HSH expense.
  • hiring_company — written into the hiring tenant's records at the same moment, linked back to the subcontractor row via linked_expense_id.

For HSH work, the two rows are created atomically by the hshSyncExpense Supabase Edge Function and hold each other's id in linked_expense_id (bidirectional). Approvals, rejections, and deletes must update or remove both sides in the same transaction.

Expense creation is a two-step wizard:

  1. Step 1 — Input. Toggle between Receipt (default) and Mileage. Receipt shows the upload control; Mileage shows start/end address inputs plus a "Calculate Route" action.
  2. Step 2 — Review. Receipt mode shows the cropped image alongside editable OCR-extracted fields. Mileage mode shows a route map and an editable miles field; the amount is auto-calculated as miles × IRS_MILEAGE_RATE.

A time_entries.id may be referenced by an expense when the expense was logged against a specific time-clock session; the /approvals queue rolls time and expenses together per submitter and per trial.

Receipt Capture and OCR

  1. User opens the expense dialog from the Time Clock trial card (or from Time & Expenses).
  2. They select or photograph a receipt. The browser performs client-side crop and deskew on a canvas before upload, so only the trimmed receipt leaves the device.
  3. The cropped image uploads to the private receipts/ bucket in Supabase Storage via a server-issued signed upload URL. The bucket is not public; reads go through signed URLs scoped to the tenant.
  4. The extract-receipt Supabase Edge Function is invoked with the storage path. It calls a vision model (OpenAI GPT vision or Anthropic Claude vision — chosen per-tenant via settings) to extract vendor, amount, expense_date, and a best-guess category.
  5. The dialog prefills Step 2 with the extracted fields. The user edits any field before saving — OCR output is a suggestion, never authoritative.

The extract-receipt function is the direct replacement for the legacy Base44 InvokeLLM pattern. The vendor model and prompt live server-side; no API keys ever reach the client.

Mileage Capture

  1. User toggles to Mileage mode.
  2. They enter a start address and an end address. Both fields accept free-form addresses; no Google Places autocomplete is required.
  3. "Calculate Route" calls the mileage-route Edge Function, which queries the Google Maps Directions API and returns distance (miles), duration, and a rendered static map URL.
  4. Step 2 shows the map, a pre-filled editable miles value, and the auto-computed amount = miles × IRS_MILEAGE_RATE. The category is forced to mileage and cannot be changed here.
  5. start_address and end_address are persisted on the row for audit.

For the adjacent "hours-on-the-road" billing concept, see Travel Time.

Approve or Reject

Approvals run from /approvals with bulk-select support. The hiring-company admin is the authority for HSH expenses; the sync direction flows from hiring row to subcontractor row.

Step Regular HSH
1 Admin clicks Approve or Reject on the row (or on a bulk selection) Same, on the hiring-company row
2 Update status, approved_by, approved_at Same
3 — Check linked_expense_id
4 — hshSyncExpense updates the subcontractor row with the same status, approved_by, and approved_at
5 Insert notification for the submitter Insert notifications for the submitter on both tenants

Rejected expenses remain in the system with status='rejected' and a rejection note; they are excluded from invoice rollup. Approved expenses flow into the Create Invoices column on /billing and their receipt images are embedded into generated invoice PDFs by the Puppeteer-based render-invoice-pdf Edge Function.

Invoice Integration

Approved expenses are grouped per trial and per billing period (weekly, monthly, or per-trial, configured on tenant_firms). When an invoice is generated from /billing:

  • Expense line items appear alongside time line items under the trial.
  • For receipts, the private Storage image is fetched via a short-lived signed URL and embedded inline in the invoice PDF by the Puppeteer renderer.
  • Mileage entries render as Mileage — {start_address} → {end_address} ({miles} mi × {rate}).
  • HSH expenses appear on the hiring tenant's client invoice at the full amount; the subcontractor_amount is the payout tracked on the HSH contract, not the client charge.

HSH Cross-Tenant Semantics

Every HSH expense operation (create, approve, reject, delete) is mediated by hshSyncExpense, which is the expense counterpart to hshSyncTime. The function runs with the service role, verifies the caller's authority on both tenants via the hsh_contracts table, and mutates the two rows in one transaction. Row-level security denies direct client writes to entry_type='hiring_company' rows — only the Edge Function can produce them.
