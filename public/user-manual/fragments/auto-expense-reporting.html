Auto expense reporting turns approved expense_entries into PDF expense reports on a recurring schedule, without manual intervention. Reports are generated by a Supabase Edge Function, scheduled by Postgres pg_cron, rendered to PDF by Puppeteer, and emailed via Resend. The entire pipeline is Supabase-native — there is no Vercel Cron, no vercel.json, and no external cron provider.

This document is the v1 single-theme specification. For the manual approval workflow that feeds this pipeline, see Expense Workflows.

How it fits together

  1. Consultants log expenses on /time-tracking; entries land with status = 'pending'.
  2. Owners and admins approve entries on /approvals; approved rows become eligible for auto-reports.
  3. A pg_cron job ticks on the configured schedule and invokes the generate-expense-reports Edge Function.
  4. The function queries expense_entries, groups them, renders PDFs with Puppeteer, uploads to Supabase Storage, writes expense_reports rows, and triggers email delivery through Resend.
  5. Recipients receive the PDF by email; internal admins see the new report in Billing and on each consultant's time-tracking page.

Schedule types

Configured per tenant under Settings → Expenses (see Settings). Each tenant picks one or more of:

Schedule Cadence Grouping Typical recipient
weekly Every Monday 06:00 tenant-local for the prior Mon–Sun user_id Consultant + firm admin
bi_weekly Every other Monday 06:00 for the prior 14 days user_id Consultant + firm admin
monthly 1st of each month 06:00 for the prior calendar month user_id or tenant_id Firm admin / finance
per_trial_completion Fires the morning after a trial's end_date passes trial_id is_primary_billing contact on the trial's client_firm

Multiple schedules may run concurrently — for example, a firm can issue per-user monthly rollups and per-trial reports at completion without conflict. Each expense_entries row carries an expense_report_id once reported, which prevents double-reporting.

pg_cron configuration

All scheduled work is defined in migrations under supabase/migrations/ and deployed via supabase db push. Example:

-- Weekly per-user reports: Mondays 06:00 UTC
select cron.schedule(
  'auto-expense-reports-weekly',
  '0 6 * * 1',
  $$
    select net.http_post(
      url := current_setting('app.supabase_url') || '/functions/v1/generate-expense-reports',
      headers := jsonb_build_object(
        'Content-Type', 'application/json',
        'Authorization', 'Bearer ' || current_setting('app.service_role_key')
      ),
      body := jsonb_build_object('schedule', 'weekly')
    );
  $$
);

Additional jobs are scheduled with the same pattern for bi_weekly, monthly, and a per_trial_completion job that runs daily and internally filters trials whose end_date = current_date - interval '1 day'.

Secrets (service_role_key, base URL) are stored via ALTER DATABASE ... SET app.xxx at deploy time — never hardcoded in migrations. See Environment Setup.

Query shape

The Edge Function runs against Supabase PostgreSQL using the service role key. The canonical query, grouped per schedule type, is:

// Pseudo-TypeScript for clarity
const { data: entries } = await supabase
  .from("expense_entries")
  .select(
    "id, tenant_id, trial_id, user_id, date, amount, category, vendor, description, receipt_url"
  )
  .eq("tenant_id", tenantId)
  .eq("status", "approved")
  .is("expense_report_id", null)
  .gte("date", periodStart)
  .lte("date", periodEnd);

Grouping is done in memory by user_id, tenant_id, or trial_id depending on the active schedule.

PDF generation (Puppeteer Edge Function)

The generate-expense-reports Edge Function composes an HTML document server-side and rasterises it using a headless Chromium pinned in the function's Deno runtime. API2PDF is not used.

The PDF contains, in order:

  1. Cover page — tenant branding, report number (ER-0001), period, grouping key (consultant / trial / firm), totals.
  2. Totals by category — sum of amount per category (Lodging, Meals, Mileage, Supplies, Other).
  3. Line items table — date, vendor, description, category, amount, approved/pending flag.
  4. Receipt thumbnails — inlined from receipt_url (Supabase Storage signed URLs, 2×2 grid per page).
  5. Appendix — full-size receipt images for audit trail.

Approved vs. pending is surfaced per line item: reports only include approved entries, but any pending entries that would have been in-scope are listed in a final "Excluded — awaiting approval" section so finance teams can chase them down. This mirrors the informational panel pattern used elsewhere; it does not block generation.

The rendered PDF is uploaded to the expense-reports private bucket; a signed URL is stored on the expense_reports.pdf_url column.

Recipients and email delivery

Email is sent via Resend (see External Integrations). Recipient resolution depends on the schedule's grouping:

  • Per-user (weekly, bi_weekly, some monthly) — the consultant (user_profiles.email) plus all tenant admins and owners.
  • Per-tenant (monthly finance rollup) — all tenant admins and owners; optional CC list configured in Settings.
  • Per-trial (per_trial_completion) — the is_primary_billing = true contact on the trial's client_firm, CC'd to the trial's assigned consultants and the firm admin. Billing contact email comes from contacts.email joined through trials.client_firm_id.

The outgoing email links to a signed URL of the PDF (1-hour TTL) and attaches the full PDF when under 10 MB.

Configuration surface (Settings → Expenses)

The Expenses tab in Settings exposes:

  • Enable auto reporting — master toggle per tenant.
  • Schedules — multi-select of weekly, bi_weekly, monthly, per_trial_completion.
  • Grouping per schedule — user_id vs tenant_id for monthly; fixed for others.
  • Recipient overrides — additional CC/BCC addresses per schedule.
  • Report number prefix — defaults to ER-, editable.
  • Include pending section — toggle the "Excluded — awaiting approval" appendix.
  • Time zone — tenant-local TZ used to anchor schedule windows.

All settings live on tenant_firms.auto_expense_config (JSONB) and are read by the Edge Function at the start of each run.

Backend function reference

See Backend Functions for the full signature. In brief:

  • generate-expense-reports — invoked by pg_cron; accepts { schedule: 'weekly' | 'bi_weekly' | 'monthly' | 'per_trial_completion', tenant_id?: string }.
  • render-expense-report-pdf — internal helper; Puppeteer renderer.
  • send-expense-report-email — Resend dispatcher; handles attachment size fallback to signed-URL-only.

Related entities

Key columns introduced or relied on (full schema in Database Schema):

  • expense_reports — id, tenant_id, report_number, grouping_key, period_start, period_end, total_amount, expense_count, pdf_url, status.
  • expense_entries.expense_report_id — nullable FK; populated at report time and locks the row.
  • tenant_firms.auto_expense_config — JSONB holding the schedule configuration above.

Notifications

A system notification is written via the unified notifications pipeline (Notification System) when a report is successfully generated and when email delivery fails. Failures do not re-attempt automatically — an admin must re-trigger from the Billing page.

Edge cases

  • No approved entries in period — no expense_reports row is written and no email is sent. A single summary notification goes to admins noting "0 reports generated".
  • Per-trial completion on a same-day extension — if a trial is continued (see Expense Workflows) before its completion job runs, the job is skipped for that trial and re-scheduled for the new end_date.
  • Mixed-tenant HSH entries — hiring_company mirror rows (entry_type = 'hiring_company') are excluded; only regular and subcontractor rows are reported.
  • Time zone drift — windows are computed in the tenant's configured TZ, not UTC, to avoid off-by-one-day clipping at month boundaries.
