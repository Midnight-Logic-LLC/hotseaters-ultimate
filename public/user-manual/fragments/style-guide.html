Style Guide

The HotSeaters design system. This document captures the color palette, typography scale, spacing tokens, and component rules used across the application. The authoritative branding sources are docs/branding/hotseaters-brand-template.html and docs/branding/hotseaters-brand-guide.html — this guide summarizes them for day-to-day implementation.

For the larger picture, see App Overview, Design Patterns, and Technical Reference.

Theme scope (v1). HotSeaters ships a single light theme in v1. Dual-theme (light + dark) support is deferred. All tokens below describe the v1 light theme. Do not reach for dark: variants or conditional theme switching in new components.

Brand Identities

HotSeaters contains two distinct brand surfaces. They must remain visually separate.

Surface Palette Where it applies
HotSeaters (core app) Cyan / blue / orange Deals, trials, clients, invoicing, schedule, team
HotSeatHub (marketplace) Purple / indigo Gig postings, HSH responses, subcontractor network, favorites

Never mix palettes across surfaces. HSH elements are always paired with the marketplace-specific icon treatment (see Design Patterns).

CSS variable example

Define semantic tokens as CSS custom properties so components stay theme-aware:

:root {
  --color-bg-page: #FAFAF9;
  --color-surface-card: #FFFFFF;
  --color-border-default: #E7E5E4;
  --color-text-heading: #1C1917;
  --color-text-body: #57534E;

  --color-brand-primary: #06B6D4;   /* cyan-500 */
  --color-brand-primary-hover: #0891B2;
  --color-hsh-primary: #9333EA;     /* purple-600 */
  --color-hsh-primary-hover: #6B21A8;

  --color-status-success: #059669;
  --color-status-warning: #F59E0B;
  --color-status-danger: #DC2626;
}

Components

HotSeaters components are built on shadcn/ui over Tailwind. Prefer shadcn primitives (Card, Button, Input, Badge, Dialog, Select) before introducing custom HTML controls.

Buttons

Purpose Classes
Primary (HotSeaters) bg-cyan-500 hover:bg-cyan-600 text-white
Operations bg-blue-500 hover:bg-blue-600 text-white
Accent / CTA bg-orange-500 hover:bg-red-500 text-white
Primary (HotSeatHub) bg-purple-600 hover:bg-purple-800 text-white
Destructive bg-red-600 hover:bg-red-700 text-white
Outline border border-stone-200 text-stone-900 hover:bg-stone-50

Always include a leading icon at w-4 h-4 mr-2 when the button represents a concrete action.

Cards

  • Border: border-stone-200
  • Background: bg-white
  • Padding: p-6 for content
  • Header: border-b border-stone-100 bg-white rounded-t-lg
  • Elevated variant: shadow-lg hover:shadow-xl transition-shadow
  • HSH accent variant: border-purple-200 bg-gradient-to-br from-purple-50 to-indigo-50

Inputs

  • Use shadcn's Input, Textarea, Select, and Checkbox primitives.
  • Border: border-stone-200
  • Focus: focus-visible:ring-2 focus-visible:ring-cyan-500
  • Placeholder text uses text-stone-500
  • Labels use text-sm font-medium text-stone-700

Badges

Purpose Classes

Warning bg-amber-100 text-amber-700 (or bg-yellow-100 text-yellow-700)
Danger bg-red-100 text-red-700
Info bg-blue-100 text-blue-700

Role-specific badges: Owner → purple, Admin → blue, Sales → green, Trial Consultant → stone.

Modals

  • Use shadcn's Dialog for all modals.
  • Consistent size tokens: sm (max-w-sm), md (max-w-md), lg (max-w-2xl), xl (max-w-4xl).
  • Footer pattern: outline Cancel on the left, primary action on the right.
  • Include a short description under the title for anything more complex than a confirmation.

Empty states

Empty states should show an icon, a short title, a one-sentence description, and a single primary action that unblocks the user.

Metric cards

Summary metric tiles follow this anatomy: small label, large value, optional delta percentage, and a tinted icon badge. Use semantic colors for positive (green) and negative (red) deltas.

Interactive states

State Pattern
Hover (card) hover:shadow-lg transition-shadow
Active / selected bg-cyan-50 border-cyan-300 (HotSeaters) or bg-purple-50 border-purple-300 (HSH)
Disabled opacity-50 cursor-not-allowed
Loading animate-spin spinner in brand-primary color
Focus (keyboard) focus-visible:ring-2 focus-visible:ring-offset-2 with brand-primary ring

All interactive elements must have visible focus states — do not suppress the ring.

Icons

The app uses lucide-react as its icon library. Use icons intentionally, never purely decoratively. Group usage into these categories:

  • Navigation & structure — dashboard, sidebar, and section affordances.
  • Sales & finance — deals, invoicing, payments, reporting.
  • Operations — trials, schedule, time tracking, approvals.
  • People — team, contacts, consultants, roles.
  • Marketplace (HotSeatHub) — gig postings, favorites, subcontractors; always color-paired with the HSH palette.
  • Status & feedback — success, warning, error, info indicators.
  • Actions — create, edit, delete, upload, download.

Keep icon sizes consistent: w-4 h-4 inside buttons and inline affordances; w-5 h-5 or w-6 h-6 for section headers and feature tiles.

Brand separation rules

  • HotSeaters palette (cyan / blue / orange) is reserved for core app features.
  • HotSeatHub palette (purple / indigo) is reserved for marketplace features and is always paired with the HSH icon treatment.
  • Do not mix palettes across surfaces. Status colors (green / amber / red / blue) are shared.
  • Gradients: HotSeaters uses cyan → blue → orange; HotSeatHub uses purple → indigo.

Deferred

  • Dual-theme (light + dark) support. v1 ships light only; dark-mode tokens and dark: variants are out of scope. When dual theme returns, token definitions should move into :root / [data-theme="dark"] CSS variable blocks rather than Tailwind dark: class variants.
  • Per-tenant theme overrides. Customer-level theme customization (colors, fonts, radii) is not part of v1.
