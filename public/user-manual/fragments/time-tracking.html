Time Tracking

The Time Tracking page is a multi-tab data-entry surface for logging billable time, reviewing entries, managing expenses and reports, and requesting time off. Approvals live on the dedicated Approvals page, and invoice creation lives on Billing.

All data is persisted in the Supabase time_entries and expense_entries tables, scoped by tenant_id. Receipt extraction runs in the extract-receipt Edge Function. The active tab is persisted to user_profiles.preferences.myWorkHubTab. Related: Time Clock Workflows, Expense Workflows, Travel Time, Auto Expense Reporting.

Tab 1 — Time Clock

Real-time timer interface. Features:

  • Pick a trial, then a service, to start the timer. Only trials and services the user is assigned to (via assignments) are listed.
  • HSH subcontract gigs appear as separate purple-themed entries.
  • Start creates an in-progress time_entries row. Stop finalizes it with end time, duration, rate, and amount. Cancel deletes the in-progress row.
  • Time rounding is applied on clock-in and clock-out per tenant settings (nearest, up, or down).
  • Manual-entry mode captures time after the fact (start time, end time, description).
  • For HSH work, creates bidirectional linked entries: entry_type = 'subcontractor' in the subcontractor's tenant and entry_type = 'hiring_company' in the hiring tenant. The pair is joined by linked_time_entry_id.
  • Supabase Realtime subscriptions update the UI without polling.
  • The tenant setting hide_deals_from_time_clock suppresses deal-stage trials from the dropdown.

Tab 2 — Time Table

Spreadsheet view of time entries with KPI cards for Today, This Week, This Month, and Pending Approval hours.

Date filter

Dropdown presets: Today, This Week, This Month, Last Week, Last Month, This Year, Last Year, and Custom (opens a dual-month range calendar picker). Filters all rendered entries to the selected range.

Group-by toggles (owner / admin only)

Three independent switches that compose hierarchically (Team → Trial → Person). Each is persisted to user_profiles.preferences.time_tracking:

  • Group by Team (groupByTeamSpreadsheet) — Visible only when tenant_firms.marketplace_post_jobs is enabled. When ON, splits the spreadsheet into two bordered sections:
    • "[Tenant Name] Team" — Regular and subcontractor entries where tenant_id matches.
    • "HotSeatHub Subcontractors" — hiring_company entries (work performed by external subcontractors for your tenant), with names and photos resolved from the HSH contract.
    When OFF, everything collapses into a single "All Team Members" section.
  • Group by Trial (groupByTrialSpreadsheet) — Within each team section, entries are grouped under collapsible trial headers showing case name and per-trial totals.
  • Group by Person (groupByPersonSpreadsheet) — Within each team / trial section, entries are grouped under collapsible person headers with photo and per-person totals.

Additional controls

  • My Time / All Time — Owner / admin only. "My Time" filters to rows where consultant_id matches the current user; "All Time" shows all tenant entries.
  • + Time Entry — Opens a manual-entry row inline at the top of the spreadsheet.
  • Editable inline cells for start time, end time, description, and rate.
  • Approve / Reject / Reset actions per row (owner / admin) and bulk selection with Select All and batch actions.
  • Status color coding: pending (yellow), approved (green), rejected (red), billed (blue).
  • HSH entries render subcontractor names resolved from the linked HSH contract snapshot.

Approval mode vs. spreadsheet mode

The same spreadsheet component is shared with the Approvals page (approvalMode = true). In approval mode:

  • Group by Team splits into three sections: Internal Team, HotSeatHub Subcontractors, and HotSeatHub Assignments (your consultants' entries written into other tenants' books).
  • Each section has its own Select All button for bulk operations.
  • A bulk action bar appears when rows are selected: Approve, Reject, Reset to Pending, Clear.

Tab 3 — Expenses

Expense management with KPI cards for This Month, Pending Reimbursement, and Unbilled totals.

Expense list

The expense list reuses the same component as the Approvals page:

  • Status filter tabs — All, Pending, Approved, Rejected, Billed, Reimbursed.
  • Date filter — Today, This Week, This Month, Last Week, Last Month, This Year, Last Year, Custom.
  • Group by Team / Trial / Person — Three independent toggles, composed hierarchically. Person defaults to ON. Preferences persist to user_profiles.preferences.
  • Search — Filters by description or category.
  • My Expenses / All Expenses — Owner / admin can view tenant-wide expenses.
  • Add Expense — Opens the expense wizard.
  • Expense tables use fixed layout with explicit column widths so receipt and mileage rows align cleanly.
  • Each row shows checkbox, date, person (when not grouped), trial / client (when not grouped), description, category badge, amount, receipt icon (opens the document viewer dialog), and edit / delete buttons.
  • Edit and Delete are only available while the expense is in pending status. Deleting an HSH-linked expense also deletes its bidirectional counterpart.

Add Expense wizard

A two-step flow that branches on expense type.

Step 1 — type selection and data capture

  • Receipt mode — Drag-and-drop upload zone accepting images and PDFs; on mobile the same control triggers the camera or file picker. On upload:
    1. The file is stored in Supabase Storage.
    2. For images, an Edge Function straightens, crops, and cleans the photo to produce a scan-quality image.
    3. The extract-receipt Edge Function calls the configured AI provider to extract amount, date (YYYY-MM-DD), description, category (one of the eight predefined values), and merchant name.
    4. On success a toast confirms the extraction and advances to Step 2 with fields pre-filled.
  • Mileage mode — Two address inputs with Google Places autocomplete:
    • Start Address (green pin) — Place names, street addresses, or business names; biased to the user's detected location.
    • End Address (red pin) — Biased toward the start address.
    • Current IRS rate display (2025 standard mileage rate).
    • Calculate Route — Calls the calculate-route Edge Function which uses the Google Maps Directions API to compute distance and generate a static map image. Returns miles, duration, and map URL.

Step 2 — expense form

A three-column form pre-filled from Step 1:

  • Column 1 — Receipt / map preview: receipt image with rotate (90° L/R), View Full Size, Remove, Retry Image Processing, and Retry Data Extraction; or the Google Maps static route with start / end pins, distance, and IRS rate.
  • Column 2 — Core details: amount (auto-computed for mileage = miles × IRS rate, editable for receipts), date, Paid To (receipts, required), Miles (mileage, editable; amount recalculates live), description (required).
  • Column 3 — Classification: category (travel, meals, lodging, materials, equipment, software, parking, other; locked to "travel" for mileage), trial selector (owner/admin sees all operations-stage trials; others see only trials they are assigned to — client is derived from the trial), and Reimbursable / Billable to Client toggles (default ON).

Validation requires amount > 0, description, trial, and either paid_to (receipt) or miles (mileage). For mileage, the static map URL is saved in receipt_url so it shows in receipt previews.

HSH bidirectional expenses

When the wizard is opened from an HSH subcontract context, submitting creates two linked expense_entries rows — one in the subcontractor's tenant (entry_type = 'subcontractor') and one in the hiring tenant (entry_type = 'hiring_company') — joined via linked_expense_id. Deleting either row deletes its counterpart.

Tab 4 — Expense Reports

Read-only view of generated expense reports for the current user (owner / admin see all with an All / Mine toggle). Each card shows report number, period, consultant, expense count, total, and status. Click to view or download the generated PDF. Consultants cannot modify or delete reports. Reports are generated by admins from the Billing page during period close.

Tab 5 — Time Off

Time-off request management. Uses a standalone entity with its own approval workflow, independent from time and expense approvals.

Consultant view

  • Request Time Off — Leave type (Vacation, Sick Leave, Personal Day, Other), date range, optional notes.
  • View own requests — Filtered to the current user by default.
  • Delete — Consultants can delete their own pending requests.
  • Status tracking — Pending / Approved / Denied per request.

Owner / admin view

  • Show Mine / Show All — View tenant-wide requests.
  • Approve / Deny — Available on any pending request that isn't their own.
  • Delete — Admins can delete any request regardless of status.
  • Pending badge — Tab header shows pending request count from other consultants.

Special rules

  • Owner auto-approval — When the tenant owner creates a request, it is automatically Approved.
  • Cannot self-approve — Admins cannot approve or deny their own requests.
  • Year filter — Requests are filtered by year based on start_date.
  • Timeline integration — Approved time-off renders as a colored bar behind the consultant row on the [Schedule](/user-manual/schedule) Gantt.

Entity mappings

  • TimeEntry → time_entries
  • Expense → expense_entries
  • TrialServiceAssignment → assignments
  • UserInfo → user_profiles + user_roles
  • company_id → tenant_id (enforced by RLS on every query)
