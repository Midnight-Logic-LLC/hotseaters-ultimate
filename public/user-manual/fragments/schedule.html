Schedule

The Schedule page is a Gantt-style interactive timeline for every active trial, its services, and every consultant assignment. It supports drag-and-drop date editing for both trial bars and individual task bars, with cascading updates to child services.

Data is persisted in the Supabase trials, trial_services, and assignments tables and scoped by tenant_id. Drag-drop mutations fire Supabase Realtime events so teammates see changes immediately, and they enqueue notification emails via Resend. Related: Trials, Time Tracking, Notification System.

Overall function

The timeline shows all scheduled trials and their service tasks on a horizontal time axis. The dataset includes own-tenant trials, HotSeatHub subcontract gigs (where your tenant provides consultants to another), and pending marketplace responses. Completed trials that were lost or settled are excluded.

Toolbar controls

  • By Trial / By Consultant toggle — Groups timeline rows by trial or by consultant. Persisted to user_profiles.preferences.schedule_view_by.
  • Deals switch — Show/hide items still in sales pipeline stages. Persisted to preferences.schedule_hide_deals.
  • Pre-Trial switch — Show/hide pre-trial services (service_phase = 'pre_trial', or any service whose start date falls before the trial start). Persisted to preferences.schedule_hide_pre_trial.
  • Time scale slider — Day / Week / Month / Quarter / Year. Adjusts column width and header labels. Persisted to preferences.schedule_time_scale.
  • Zoom slider — Manual zoom 1%–100%. Using it disables Fit mode.
  • Fit button — Auto-computes zoom to fit all content in the viewport; recalculates on window resize. Persisted to preferences.schedule_full_width.
  • Expand / Collapse button — Toggles full-width mode (drops the container max-width constraint).

Timeline structure

  • Left sidebar — Fixed-width, resizable column (drag the divider). Shows trial or consultant names, nested service names, consultant avatars, and assignment status.
  • Timeline area — Horizontally scrollable. Renders date-column headers, weekend shading, a red "today" indicator, and the bars.
  • Trial bars — Colored bars spanning trial start to end. Blue for trials, gray for deals, purple for HSH gigs. Clicking opens the Trial Summary modal.
  • Service bars — Narrower bars for individual services. Light shade = hourly billing, dark shade = daily-minimum billing. Split-billing services render as two adjacent bars.
  • Travel bars — Hatched bars rendered before and after a service bar when travel_eligible is true.

Drag-and-drop: service bars

Owner and admin users can drag service bars to adjust task dates. Three interactions are supported:

  • Move (body drag) — Shifts start and end by the same delta. End date is clamped to the trial's end date; any overflow is clipped from the start.
  • Resize start (left handle) — Adjusts start only; cannot cross the end.
  • Resize end (right handle) — Adjusts end only; constrained to the trial end.

On mouse-up, the update-service-dates Edge Function is called with the new date range. It updates the trial_services row, inserts notification rows that Supabase Realtime broadcasts to assigned consultants, sends Resend email, and optionally syncs Google Calendar.

Split-billing trigger

If a drag causes a service with has_daily_minimum = true to newly cross the trial start threshold (it was not crossing before but now is), the Split Billing dialog opens with three choices:

  • Hourly — Bill at hourly rate for the full duration (final_billing_method = 'hourly').
  • Daily Minimum — Bill at daily minimum for the full duration (final_billing_method = 'daily_minimum').
  • Split — Hourly before trial start, daily minimum during trial (final_billing_method = 'split'); rendered as two adjacent bars.

If the service was already crossing and still crosses after the drag, its existing split configuration is preserved. If it was split but no longer crosses, it auto-converts to hourly (entirely before) or daily_minimum (entirely during).

Restrictions

  • HSH subcontract-gig service bars cannot be dragged (the subcontractor tenant has no authority to move them).
  • Pending marketplace service bars cannot be dragged.
  • Only owner and admin roles can drag (`canEditDates` check).
  • If the service has assignments, an Update Progress modal shows the notification-sending status after the drop.

Drag-and-drop: trial bars

Dragging a trial bar cascades date changes to every child service bar within that trial. Three interactions with distinct cascading rules:

Move (body drag)

Shifts trial start and end by the same number of days. All child services shift by the same delta (both start and end).

Resize start (left handle)

Changes only the trial start. Child services cascade as follows:

  • In-trial-only services — Start moves with the trial start; end unchanged.
  • Pre-trial / both services, start date — Always moves with the trial start.
  • Pre-trial / both services, end date — Moves with the trial start only if it falls in the first half of the original trial range (before the midpoint); otherwise stays fixed.

Resize end (right handle)

Changes only the trial end. Child services cascade as follows:

  • In-trial-only services — End moves with the trial-end delta; start unchanged.
  • Pre-trial / both services, end date — Moves with the trial end only if it falls in the second half of the original trial range (after the midpoint); otherwise stays fixed.
  • Pre-trial / both services, start date — Always unchanged.

Visual feedback and backend processing

While dragging, the trial bar and all affected service bars update in real time via direct style updates. Split-billing bars update both portions; travel bars shift their day-before/day-after positions; label containers slide with the bars. On mouse-up, the update-trial-dates Edge Function is called with the new trial range and an array of service-date updates. It atomically updates the trials row and all affected trial_services rows in a single transaction, writes notification rows (Realtime + Resend email), and optionally syncs Google Calendar. An Update Progress modal reports notification status for trials with assignees.

Restrictions

  • HSH subcontract-gig trial bars cannot be dragged.
  • Only owner and admin roles can drag.
  • If start and end are unchanged after drop, the mutation is silently skipped.

Service Assignment modal

Opened by clicking a service in the sidebar or on its bar. A two-column dialog for managing who works on a specific service task. Only owner and admin can change assignments.

Left column — service info

  • Service name, daily-minimum badge (if applicable), location, and date range.
  • Rate display: $/hour for hourly, $/day for daily minimum, or a split-billing breakdown.
  • Override button to change the rate (updates trial_services.rate directly).
  • Split-billing panel — appears when a daily-minimum service crosses the trial start. Shows current method and a Settings button that re-opens the Split Billing dialog.

Right column — internal team assignment

  • Checkbox list of qualified consultants — filtered via service_qualifications to those who hold the matching service_id. Unqualified consultants are not shown.
  • Pre-checked for currently assigned consultants (assignments rows where is_subcontractor = false).
  • Assign Selected (N) — diffs current checkboxes against the initial state and creates or deletes assignments rows. Runs through a single Edge Function that also creates or deletes Google Calendar events and emits assignment / unassignment notifications.

HotSeatHub section

Visible only when tenant_firms.marketplace_post_jobs is enabled. Rendered full-width below the team column with a purple top border.

  • Assigned HSH subcontractors — Checkbox list of subcontractor consultants currently linked via the HSH contract. Unchecking and confirming removes the assignment in both tenants, deletes the mirror calendar events, and sends an unassignment notification.
  • "Posted to HSH" badge — Shown when an active HSH request exists for this trial + service; indicates the task is on the marketplace awaiting responses.
  • Pending responses — If responses exist on the active request, each is shown as a card with company and consultant names, proposed rate, a rate-comparison badge (agreed / counter), a message, and action buttons. Owner can Accept (creates assignment) or Decline. A Favorite button adds the company / individual to the favorites network.
  • Post to HotSeatHub — Shown only when no active request exists. Opens an inline form with: rate input (auto-suggested from profit-margin settings), public / private toggle, audience selector (companies or individual consultants, including favorites), and a description.
  • Suggested rate — For the private-margin case, subtracts the tenant-configured profit-margin value (percentage or dollar amount) from the service rate to suggest the subcontractor payout.

Subcontractor's own-gig view

When a user opens an HSH subcontract service where their own tenant is the subcontractor, the modal switches to a read-only view:

  • Service info card with a purple "You are assigned via HotSeatHub" badge.
  • Hiring tenant (client) name.
  • List of any other HSH consultants assigned to the same service by the hiring tenant.
  • No assignment controls — the subcontractor cannot modify assignments on the hiring tenant's service.

Bar color legend

  • Light blue — Trial service, hourly billing.
  • Dark blue — Trial service, daily-minimum billing.
  • Light purple — HSH subcontract, hourly.
  • Dark purple — HSH subcontract, daily-minimum.
  • Light gray — Deal service, hourly.
  • Dark gray — Deal service, daily-minimum.

Continued trials

Trials with completion_type = 'case_continued' render specially: definite dates show normal bars, month-only renders a shaded month span, and "none" hides the end date from timeline calculations until a date is set.
